## What is "Generated Code"?

Generated code is every file `sce-codegen` writes when it is run on an
input document, in any target language, for example:

```bash
sce-codegen generate your_state_machine.scxml -o output/ -l cpp
```

A file is generated code whether or not it carries a licence header.

The same permission covers what SCE's authoring tools (`tools/authoring`)
return from your document — pseudocode, scaffolds, review reports —
whether you call them from the command line or through their MCP server.

## Who Owns What

Generated code is made of two kinds of material:

- **Material derived from your input document** — state and event names,
  guard and action expressions, data, the structure of your machine. It
  is yours. SCE claims nothing in it.
- **Material copied from SCE's templates** — the W3C SCXML algorithms,
  the policy scaffolding, the helper calls. Its copyright stays with SCE.
  You receive it under AGPL-3.0 with the Linking Exception, which lets you
  use it under terms of your choice within the two conditions above.

Each generated file's header states both:

```
SPDX-License-Identifier: AGPL-3.0-only WITH LicenseRef-SCE-Linking-Exception OR LicenseRef-SCE-Commercial
SPDX-FileCopyrightText: <year> <author of the input document> (content derived from the input document)
SPDX-FileCopyrightText: 2025-2026 newmassrael (content copied from SCE templates)
```

## Why Not MIT

Earlier releases placed all generated code under MIT. The templates carry
the engine's algorithms — the C11 backend, for instance, writes the W3C
microstep into every generated file — so running the generator on a rich
input document produced an MIT-licensed copy of engine logic that could
be lifted into a competing product with no obligation. The two conditions
above close that path while leaving ordinary use free.

This follows the model of the Bison parser generator, whose skeleton
exception lets a generated parser be used under any terms unless the work
is itself a parser generator.

## Frequently Asked Questions

### Can I use generated code in my commercial product?

**Yes**, if the generator was unmodified and your product is not a
competing product. Closed source is fine.

### Do I need to include a licence notice in my product?

Keep the header of each generated source file you distribute, and name
SCE, AGPL-3.0 and the Linking Exception in your documentation or "About"
screen, as the Linking Exception section 2 asks for the engine.

### May I edit the generated code?

**Yes.** Editing the output after it is produced does not end the
permission. What ends it is producing the output with a modified
generator or modified templates.

### What if I modify `sce-codegen` or its templates?

The generator is part of SCE and is licensed like the engine. A modified
generator, and the output it produces, are governed by AGPL-3.0 in full,
unless you hold an SCE Commercial License.

### Do I need a commercial license for the generator tool?

**No**, to run the unmodified generator for your own application. **Yes**,
to modify it and keep the changes private, or to build a competing product
on it without releasing that product under AGPL-3.0.

### Do I need a commercial license for the runtime engine?

**It depends:**
- **Using the unmodified engine in your application**: AGPL-3.0 + Linking
  Exception (FREE, static or dynamic linking, open source or proprietary
  OK)
- **Modifying the engine for proprietary use**: Commercial License —
  contact newmassrael@gmail.com for pricing

## Example Usage Scenarios

### Scenario 1: Open Source Robot Project

```bash
sce-codegen generate robot_controller.scxml -o src/ -l cpp
cmake .. && make
```

**License requirements:** None beyond the notices, whatever licence the
project uses: the engine and the generator are unmodified.

### Scenario 2: Commercial Medical Device (Proprietary)

```bash
sce-codegen generate device_controller.scxml -o src/ -l cpp
cmake .. && make
```

**License requirements:** None beyond the notices, as long as the engine
and the generator are unmodified. A patched engine kept private needs the
Commercial License.

### Scenario 3: A State-Machine SDK Built on SCE

**License requirements:** This is a competing product. Either release the
whole SDK under AGPL-3.0, or obtain the Commercial License.
